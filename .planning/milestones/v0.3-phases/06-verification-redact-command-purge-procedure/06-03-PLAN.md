<objective>
Ship `git turn redact <N>` — a post-hoc command that scrubs a specific turn's captured `prompt` field
from the note, for the case where a secret made it in anyway.

Purpose: REDACT-02. Redaction on the write path (Phase 4/5) is preventive; this is the remediation
path. Per D-01 only the freeform `prompt` field is scrubbed — `model`/`usage`/`latency_ms`/
`tool_summary` are structured/enumerable and are not where a leaked secret realistically lives. Per
D-02 it runs immediately with no confirmation prompt, matching `revert`/`redo`.
Output: new `src/commands/redact.js`, new `src/commands/redact.test.js`, `bin/git-turn` registration.

Note: redacting the note does NOT delete the old blob from the object store — that requires the purge
command built in plan 06-04. That relationship is documented there.
</objective>

    6. Write via `updateNote(NOTES_REF, noteSha, existing => ({ ...existing, prompt: '[REDACTED]' }))` —

       `require('../cache')` and call `updatePromptFields(session.session_id, turnN, { prompt: '[REDACTED]' })`;
       in `catch (e)` write `git turn: warning: cache update failed (${e.message})` to `process.stderr`.
       Without this, `log --with-prompts` would keep rendering the pre-redaction prompt from the cache.
    8. `console.log(\`Turn ${turnN}: prompt redacted\`)`.
    9. Also print a pointer to the purge step on stdout:
       `Note history still contains the old blob — run \`git turn gc --purge-notes\` to remove it.`
       (PITFALLS.md's core point: redaction alone is necessary but not sufficient.)

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-06-03 | Tampering | `src/commands/redact.js` note-write target | mitigate | Resolve `parseSnapshotMessage(turn.sha).headSha \|\| turn.sha` before calling `updateNote()` (Task 1 step 4) — copying the legacy snapshot-sha pattern would write a `[REDACTED]` note onto an unrelated object while leaving the real secret in place |
| T-06-10 | Tampering | Non-prompt note fields during redact | mitigate | Use `updateNote()`'s spread-merge (`{ ...existing, prompt: '[REDACTED]' }`) rather than a whole-note overwrite; Task 2 Test 1 asserts per-field preservation of `model`/`usage`/`latency_ms`/`tool_summary`/hook fields |
| T-06-11 | Information Disclosure | Stale pre-redaction prompt served from the SQLite read cache | mitigate | Best-effort `updatePromptFields(..., { prompt: '[REDACTED]' })` cache sync (Task 1 step 7), asserted by Task 2 Test 5 |
