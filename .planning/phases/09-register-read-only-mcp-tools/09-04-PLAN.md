<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client (stdin JSON-RPC) -> McpServer | All tools/call frames are untrusted input from whatever process the user configured |
| McpServer -> tool handlers | SDK validates arguments against each zod schema before dispatch |
| server stdout | Reserved for JSON-RPC frames only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-13 | Elevation of privilege | tool surface exposed by createServer() | mitigate | Only the 5 read-only tools are registered; no revert/bisect/redact/record-prompt registration (grep: server.js has exactly 5 register calls); AGENTS.md states write tools are not exposed |
| T-09-14 | Denial of service | malformed/invalid tools/call arguments | mitigate | zod schemas reject bad args at the SDK layer; protocol test sends { turn: 'abc' } and asserts the server still answers a subsequent tools/list |
| T-09-15 | Denial of service | compute() errors killing the stdio server | mitigate | Static test forbids process.exit and .run( in src/mcp/tools; protocol test asserts child.exitCode stays null after an isError response |
| T-09-16 | Tampering | stdout corruption by tool output | mitigate | Handlers return text via the SDK only; blame/cost progress/warning sinks are no-ops (Plan 02); existing D-01 stderr test plus new tests parse every stdout line as JSON-RPC |
| T-09-17 | Information disclosure | error text over MCP | accept | Identical to CLI stderr text for the same local user; MCP client spawned by that user with the same privileges |
</threat_model>
