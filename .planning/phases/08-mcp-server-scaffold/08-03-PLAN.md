- Split taken: `src/mcp/server.js` holds the `createServer()` factory (Phase 9 adds `registerTool` calls there), `src/commands/mcp.js` holds process-lifecycle code only.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client process -> git turn mcp (stdin) | JSON-RPC frames from whatever process the user configured to spawn the server; same trust level as any local subprocess the user explicitly launches; not network-reachable |
| git turn mcp -> MCP client (stdout) | Any non-JSON-RPC byte on stdout corrupts the protocol stream |
| bootstrap code -> process lifetime | Any process.exit reachable while the server is live kills every in-flight request |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-06 | Tampering | stdout JSON-RPC channel | mitigate | mcp.js and server.js never call console.log/process.stdout (grep acceptance criteria); D-01 line goes to process.stderr; mcp.test.js asserts every stdout line parses as JSON-RPC 2.0 |
| T-08-07 | Denial of Service | process.exit reachable from server code path | mitigate | Single process.exit(1) in mcp.js fires before serveStdio(); mcp.test.js source test asserts last process.exit index precedes serveStdio( and server.js has none; SIGINT handler uses handle.close(), not process.exit |
| T-08-08 | Spoofing / Tampering | cwd/repo scoping drift | mitigate | process.cwd() read exactly once before serveStdio and stored in repoPath (grep count = 1, source test); readSession() validates the repo is initialized before any server object exists |
| T-08-09 | Denial of Service | orphaned server after client exits | mitigate | SDK closes transport on stdin EOF (verified by the stdin.end() exit-0 test); SIGINT path destroys stdin after handle.close() so no handle keeps the loop alive |
| T-08-10 | Elevation of Privilege | malicious JSON-RPC from the spawning client | accept | Zero tools registered this phase, so tools/call has no handler to reach; the client is a process the local user chose to spawn with their own privileges; input validation for tool arguments is Phase 9 (MCP-09, zod schemas) |
| T-08-11 | Information Disclosure | D-01 stderr line includes the absolute repo path | accept | stderr goes to the same local user/client that launched the process and already knows its cwd |
</threat_model>
