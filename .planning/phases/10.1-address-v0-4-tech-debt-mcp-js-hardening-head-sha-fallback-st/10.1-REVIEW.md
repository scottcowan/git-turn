# Phase 10.1: Code Review Report

**Depth:** standard. Source files only; test files were not reviewed in depth.

## Summary

The changes are small and mostly correct. The remaining problems are incomplete hardening: terminal escape injection, unreachable shutdown paths, and negative token counts.

## Warnings

### WR-01: formatToolSummary does not strip control or ANSI escape characters

**File:** `src/commands/show.js:11-24`
**Issue:** `clean()` removes only `:`, `,`, `\r` and `\n`. A crafted note (notes can be fetched from another clone or a bundle) can put ESC (0x1b) and other C0 control characters in tool names or string values. They reach the terminal unchanged, which allows terminal escape injection. The same applies to the unsanitized `meta.model` and `meta.latency_ms` lines just above.
**Fix:** `const clean = x => String(x).replace(/[\x00-\x1f\x7f:,]/g, '').trim();` and apply the same stripping to `meta.model` and `latency_ms`.

### WR-02: Negative token counts produce negative or incorrect costs

**File:** `src/commands/cost.js:75-90`
**Issue:** `isTokenCount` accepts any finite number, including negatives and non-integers. `computeCost` then returns a negative cost, which is subtracted from `totalCost` and shown in the table. A malformed note can silently skew totals.
**Fix:** `typeof v === 'number' && Number.isFinite(v) && v >= 0`.

### WR-03: SIGINT is the only shutdown path; SIGTERM is not handled

**File:** `src/commands/mcp.js:39-47`
**Issue:** SIGINT is handled, but SIGTERM (what MCP clients usually send) is not. Using `process.once` also means a second SIGINT while closing falls back to the default handler. The force-exit timer calls `process.exit(0)` even when `handle.close()` hung, so a hung shutdown is reported as success.
**Fix:** Register the same handler for SIGTERM. Exit non-zero (or log to stderr) when the force-exit timer fires.

### WR-04: MCP tool validation is incomplete

**File:** `src/mcp/tools/diff.js:7-12`, `src/mcp/tools/show.js:7`, `src/mcp/tools/blame.js:7`
**Issue:** `Number.isInteger` accepts 0 and negative turns. They are passed to `compute` as strings, so correctness depends on the downstream parsing. `blame` only checks that `file` is a non-empty string. I found no path validation in `src/commands/blame.js`: there is no check for absolute paths, `..`, or a leading `-`. A leading `-` would be read as an option by the git subprocess (argument injection), which matters when the caller is an agent. I did not confirm how the git call is built, so this is unverified.
**Fix:** Require `turn >= 1`. In blame, reject `file` values that start with `-` and ensure the git invocation uses `--` before the path.
