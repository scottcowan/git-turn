<objective>
Build `git turn record-prompt` — the writer that finally puts prompt/model/usage/latency/tool-summary data into `refs/notes/git-turn`. Reads a single JSON blob from stdin (D-01), targets the latest turn of the current session via the turn index (D-02), redacts the prompt through Phase 4's scanner, merges via `updateNote()` (D-03), and best-effort updates the SQLite cache.

Purpose: this is the whole point of the phase and the last missing writer in the milestone — `log --with-prompts`, `show`, and `cost` already read these fields defensively but nothing has ever written them. Delivers CAPTURE-01 (merge-safe write, turn-index target), CAPTURE-02 (verbatim Anthropic `usage` shape), CAPTURE-03 (`latency_ms` pass-through), CAPTURE-04 (per-tool breakdown, D-04).

Output: `src/commands/record-prompt.js`, `src/commands/record-prompt.test.js`, command registration in `bin/git-turn`, and an AGENTS.md update replacing the stale "nothing shipped writes them yet" note.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stdin JSON → command | Untrusted, externally-supplied structured input: arbitrary types, arbitrary size, arbitrary nesting |
| free-text `prompt` → `refs/notes/git-turn` | Content may contain pasted credentials; a git note object is effectively permanent (survives overwrite until GC, out of scope for filter-repo/BFG) |
| command → SQLite cache | Derived index write, must never be able to fail the authoritative note write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `payload.prompt` → note write | mitigate | Unconditional `redact(payload.prompt)` on the raw string before any merge/stringify; no opt-out flag exists or may be added (REDACT-01). Enforced by test 7 plus the `--raw`/`no-redact` absence gate in Task 2's acceptance criteria. |
| T-05-02 | Tampering | stdin JSON payload | mitigate | `JSON.parse` in try/catch; non-object parse results rejected; `prompt` must be a string; `usage` must be a non-null non-array object. All validation runs BEFORE any note write, so a rejected payload leaves the note byte-identical (test 11). |
| T-05-03 | Tampering (data integrity) | note write racing the post-commit hook | mitigate | Writes go exclusively through plan 01's `updateNote()` bounded read-compare-retry; `addNote` is not imported (grep gate). Hook fields asserted intact by tests 1, 2, 11. |
| T-05-10 | Denial of Service (crash) | `redact()` throwing on non-string input (Phase 4 WR-01) | mitigate | Type guard precedes the `redact()` call; non-string `prompt` exits 1 with a clear message instead of an unhandled throw. |
| T-05-11 | Tampering | wrong commit annotated (bare `HEAD` drift) | mitigate | Target resolved via `listTurns()` + `parseSnapshotMessage()`; `headSha()` is never called (grep gate). Test 3 proves the note lands on the turn's commit even when current HEAD has moved past it. |
| T-05-12 | Repudiation | operator-supplied metadata is unauthenticated (a caller can claim any model/usage) | accept | Single-operator local forensics tool with no trust boundary between the operator and the repo; note history (`git log refs/notes/git-turn`) preserves prior values for audit. No signing in scope. |
