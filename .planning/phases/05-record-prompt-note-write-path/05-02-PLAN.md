<objective>
Extend the SQLite read cache to hold the two prompt-capture fields it currently cannot store (`usage`, `tool_summary`) and add the narrow `updatePromptFields()` writer that `record-prompt` will call best-effort.

Purpose: `src/cache.js`'s `turns` table already has `prompt`/`model`/`latency_ms` but no `usage` or `tool_summary` column, so a `record-prompt` write would be invisible to the cached read paths (`log`, `cost`) and a cache rebuild would drop the data. CAPTURE-02 (Anthropic-shape `usage`), CAPTURE-03 (`latency_ms`) and CAPTURE-04 (per-tool breakdown, D-04) all need a durable cache column. `COALESCE(?, column)` implements D-03's merge semantics at the SQL layer so the cache never destroys previously-indexed fields.

Output: guarded `ALTER TABLE` migration inside `openDb()`, `usage`/`tool_summary` threaded through `upsertTurn()`, a new exported `updatePromptFields()`, and `src/cache.test.js` — the first dedicated test file for this module.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| note JSON (`meta`) → SQLite row | Note content originates outside the cache and may be arbitrary JSON of arbitrary shape |
| caller arguments → `updatePromptFields` | Values flow in from a CLI payload (plan 03) and are interpolated into a SQL statement |
| on-disk legacy `cache.db` → current schema | A pre-v0.3 database file can predate the code reading it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04 | Tampering (SQL injection) | `updatePromptFields`, `upsertTurn` | mitigate | All values bound through `db.prepare(...).run(...)` positional parameters; no string interpolation of caller data into SQL. Column/table names are literals in source only. |
| T-05-07 | Tampering (data integrity) | guarded `ALTER TABLE` | mitigate | Catch narrowed to `/duplicate column name/i`; any other SQL error re-throws so a genuinely broken schema fails loudly instead of leaving the cache silently wrong. Pinned by `src/cache.test.js` test 2. |
| T-05-08 | Information Disclosure | `prompt`/`usage` copied into `cache.db` | accept | The cache is a derived index inside `.git/git-turn/`, never pushed, and receives only content that has already passed Phase 4 redaction on the write path (plan 03 T-05-01). No additional control needed at this layer. |
| T-05-09 | Denial of Service | legacy db missing columns causes `no such column: usage` on every read | mitigate | Migration runs inside `openDb()` on every process start, before any query executes. Pinned by `src/cache.test.js` test 3. |
| T-05-SC | Tampering | npm/pip/cargo installs | n/a | No packages installed this phase — `package.json` unchanged, `node:sqlite` is a Node builtin already in use. No slopcheck needed. |
