## Info

### IN-01: `gridMaxCount` recomputes over the full grid on every call from `run()`, duplicating work `buildWeekColumns` already did

**File:** `src/commands/heatmap.js:197-199, 341`
**Issue:** `gridMaxCount(grid)` walks every slot of the grid via `grid.flat().map(...)` immediately after `buildWeekColumns` has already iterated every slot to build it. This is not a performance concern in scope for this review (grid is capped at `MAX_WEEKS * 7 = 371` slots), but it does mean the max-count bookkeeping is now split across two full passes instead of accumulated during grid construction. Purely a style/architecture observation, not a correctness issue — the separate pure function is arguably better for testability (as shown by the dedicated `gridMaxCount` describe block), so this is not a strong recommendation, just a note for a future reader who might be tempted to inline it back into `buildWeekColumns` for a marginal reason and lose the clean pure-function boundary that made the WR-01 regression tests possible.
**Fix:** No action needed. Keeping `gridMaxCount` as a separate, independently-tested pure function is the right tradeoff; this note is informational only.
