<objective>
Close the single blocking gap from `03.1-VERIFICATION.md` (originally code review finding **WR-01**): `run()` scales the heatmap's density levels against the ENTIRE all-time turn history (`Math.max(...dayMap.values())`) instead of against the bounded grid actually rendered to the user.

Purpose: The gap defeats the core visual purpose of the heatmap for D-01. Any repo whose busiest day falls outside the rendered window (older than the `MAX_WEEKS=53` cap, or narrowed off-screen by `availableWeeks()`) renders every visible cell collapsed toward level 1, never reaching level 4. This was independently reproduced by the verifier with synthetic data: one off-window day at count=500 plus in-window days at count=3 rendered every visible cell as `.` instead of `#`.

This is a bug fix, not a documentation choice. The header comment (`heatmap.js:9-14`), the `bucketFor()` comment (`heatmap.js:39-42`), AGENTS.md, both prior SUMMARY files, and Plan 03.1-01's own `must_haves.truths` all promise the opposite of shipped behavior. No artifact anywhere records an intent to scale against all-time history.

Output: `run()` scoped to the rendered grid, an exported pure `gridMaxCount()` helper, regression tests that reproduce the exact synthetic failure scenario, and comment/AGENTS.md wording made precise about window scoping.
</objective>

<interface_contract>
New export added to `src/commands/heatmap.js` (used by tests and by `run()`):

```
gridMaxCount(grid) -> number
```

- `grid` is the value returned by `buildWeekColumns(dayMap, { endDate, weeks })`: a `Array<Array<{ date: string|null, count: number }>>` of `weeks` columns, each of length 7.
- Returns the highest `count` across every slot in every column, or `0` when the grid is empty or every slot is zero. Never returns `-Infinity` (the `Math.max()` no-args trap) and never throws on a very wide grid (spread over 53*7=371 slots is well inside the argument limit, but the implementation must not depend on that).

Existing signatures used, unchanged:
- `bucketFor(count, maxCount)` — density level 0..4
- `renderGrid(grid, { maxCount, useColor })`
- `buildWeekColumns(dayMap, { endDate, weeks })`
- `availableWeeks(columns)` — `availableWeeks(10)` === 3
- `DENSITY_GLYPHS` order: `[' ', '.', ':', '+', '#']` (index === density level)
</interface_contract>
