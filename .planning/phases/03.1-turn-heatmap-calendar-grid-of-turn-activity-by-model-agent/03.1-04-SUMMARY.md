# Phase 03.1 Plan 04: Window-scoped heatmap density (WR-01 gap closure) Summary

**Fixed `git turn heatmap` to scale density levels against the rendered grid's own busiest day instead of the entire all-time turn history, closing the WR-01 gap from 03.1-VERIFICATION.md.**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-09-08
- **Tasks:** 2 completed
- **Files modified:** 3 (`src/commands/heatmap.js`, `src/commands/heatmap.test.js`, `AGENTS.md`)

## Accomplishments

- Added exported `gridMaxCount(grid)` pure helper and rewired `run()` to use it as the density denominator instead of `Math.max(...dayMap.values())`
- Added unit coverage for `gridMaxCount` (normal grid, all-zero grid, empty array, off-window `dayMap`) plus a composed `bucketFor` regression case that asserts both the fixed and buggy behavior side by side
- Added two integration tests: a WR-01 regression reproducing the verifier's exact synthetic scenario (off-window burst + narrow terminal), and a "normal case" non-regression test
- Manually confirmed the regression test actually detects the bug by temporarily reverting the fix, observing the test fail, then restoring the fix and re-confirming green
- Corrected the module header comment, `bucketFor()`'s comment, and AGENTS.md's heatmap paragraph to describe window-scoped density accurately, citing WR-01/plan 03.1-04 so a future reader does not "fix" it back

- Left `computeSummaryStats(dayMap)` and the "earlier turns outside the window" disclosure logic untouched, since both are intentionally all-time scoped per D-03/D-04

## Revert-and-Confirm Result (acceptance criterion)

Before/after of the fixed line (`src/commands/heatmap.js`, previously line 320, now inside `run()`):

- **Before (buggy, shipped):** `const maxCount = Math.max(...dayMap.values());`
- **After (fixed):** `const maxCount = gridMaxCount(grid);`

Confirmed both directions:

1. **Reverted to the buggy line**, ran only the new regression test (`node --test --test-name-pattern="WR-01 regression"`): **FAILED** — `AssertionError: expected a '#' cell in a weekday row`, with the weekday rows showing `:` (level 2) instead of `#` (level 4), exactly reproducing the verifier's synthetic failure.
2. **Restored the fix**, re-ran the full heatmap suite: **50/50 pass, 0 failures** (up from 43 before this plan — 7 new tests: 5 unit `gridMaxCount`/composed cases + 2 integration tests).

## New Test Names Added

- `describe('gridMaxCount', ...)`:
  - `returns the highest count across all slots of all columns`
  - `a grid whose every slot is count: 0 returns 0, not -Infinity`
  - `an empty array returns 0`
  - `a buildWeekColumns result over a dayMap with an out-of-window high day returns only the in-window max`
  - `D-01 (WR-01 regression): bucketFor composed with gridMaxCount reaches level 4 for the in-window busiest day, while composing with the all-time dayMap max does not`
- Integration (`describe('heatmap command (integration)', ...)`):
  - `D-01 (WR-01 regression): an off-window activity burst does not flatten the in-window grid — in-window busiest day still reaches level 4`
  - `D-01: the "normal" case is unchanged when the all-time busiest day is already inside the window`
