<interface_contract>
Every exported name, signature and return shape below is fixed by this plan. Plan 02 consumes them verbatim — do not rename or reshape them.

- `dayKey(isoTs)` -> `'YYYY-MM-DD'` string, built from LOCAL date components of `new Date(isoTs)`.
- `groupByCalendarDay(turns)` -> `Map<string, number>` mapping `dayKey` to turn count. Input is the `listAllTurns()` shape: objects with at least a `ts` ISO-8601 string.
- `bucketFor(count, maxCount)` -> integer `0..4`. `0` when `count === 0`; otherwise `Math.min(4, Math.max(1, Math.ceil((count / maxCount) * 4)))`.
- `computeSummaryStats(dayMap)` -> `{ totalTurns, activeDays, busiestDay, busiestCount, firstDay, lastDay, longestStreak, currentStreak, avgPerActiveDay }`.
- `availableWeeks(columns)` -> integer number of week columns that fit. `columns` is `process.stdout.columns` (may be `undefined`).
- `buildWeekColumns(dayMap, { endDate, weeks })` -> `Array<Array<{ date: string|null, count: number }>>`, outer length `weeks` (oldest column first), each inner array length 7 indexed by `getDay()` (0 = Sunday).

Constants also exported for Plan 02: `LABEL_WIDTH = 4`, `CELL_WIDTH = 2`, `MAX_WEEKS = 53`.
</interface_contract>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git refs/notes/SQLite cache -> heatmap process | Turn metadata (`ts` strings) originates from commit messages and the cache; a malformed or hostile `ts` crosses into date parsing |
| heatmap process -> stdout | Rendered text may be piped into another program (Plan 02 handles the ANSI half of this) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03.1-01 | Denial of Service | `buildWeekColumns` window sizing | mitigate | `MAX_WEEKS = 53` hard cap plus `availableWeeks()` clamp — a repo with years of turns can never generate an unbounded grid or unbounded loop |
| T-03.1-02 | Tampering | `dayKey(isoTs)` parsing an attacker-influenced commit-message `created` line | mitigate | `new Date(isoTs)` never executes input; an unparseable `ts` must yield an `Invalid Date` that is skipped rather than producing `NaN-NaN-NaN` keys — assert non-crash behavior on the empty/degenerate inputs already in the test list |
| T-03.1-03 | Information Disclosure | Summary stats output | accept | Only turn counts and dates are emitted, all already visible via `git turn log`; no prompt text, no file contents, no secrets |
| T-03.1-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new dependencies this phase (RESEARCH.md Package Legitimacy Audit skipped for that reason). Any `npm install` in this plan is a deviation and must be rejected, not approved |
