# Phase 03.1: Turn heatmap - Context

**Gathered:** 2026-09-07
**Status:** Ready for planning

<domain>
## Phase Boundary

`git turn heatmap` — a calendar-grid view of turn activity across all sessions, colored by activity density, with a summary stat block below the grid. One-shot CLI print, no interactivity.

</domain>

<decisions>
## Implementation Decisions

### Coloring metric
- **D-01:** Color intensity = turn count per day (activity density), not model or cost. No shipped turn has `model`/token-usage data yet (Phase 4, prompt capture, not built) — confirmed via `git turn cost` showing "(no model recorded)" on every historical turn. Building model- or cost-colored cells now would render every cell empty/inert until Phase 4 ships. Re-coloring by cost-per-day is an explicit follow-up phase once Phase 4 lands real token/usage data — same grid rendering code, different value feeding the color scale.

### Data scope
- **D-02:** All sessions, cross-session — matches `blame`/`bisect`'s convention (not `log`/`diff`'s current-session-only scoping). A calendar of activity over time is pointless scoped to one session, which rarely spans multiple days.

### Time range
- **D-03:** All-time only for v1. No `--since`/range flag (the reference image's "All time / Last 7 days / Last 30 days" tabs don't translate cleanly to a one-shot CLI print). Can be added later if it turns out to matter.

### Summary block
- **D-04:** Include a stats summary below the grid, but built from turn-count/activity data only — busiest day, active days count, and similar activity-derived stats. Do NOT pull in `cost.js`'s token/dollar/model stats — those don't exist for any turn yet (same Phase 4 gap as D-01), and duplicating `cost.js`'s logic before that data exists is wasted work.

### Claude's Discretion
- Exact visual layout of the summary block (which stats, in what order) — informed by the reference screenshot but not required to match it exactly, since several of its fields (favorite model, total tokens) don't apply until Phase 4.
- Exact ANSI color steps for the density scale (how many discrete levels, which colors) — reference image showed a 4-step "Less → More" scale; reasonable to follow but not locked.

</decisions>
