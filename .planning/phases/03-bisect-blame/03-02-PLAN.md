<objective>
Implement `git turn blame <file>`: per-line attribution of every line in a file to the git-turn session and turn that last modified it, across all sessions.

Purpose: this is roadmap success criterion 1 for Phase 3 and the locked decisions D-01 (per-line, not per-file) and D-02 (all sessions, not just the current one). It closes half of the `bin/git-turn` "not yet implemented" path.

Architecture, per 03-RESEARCH.md: do NOT hand-roll line-shift tracking for tracked files. Every turn snapshot's parent is the real HEAD commit at snapshot time, so turn boundaries coincide 1:1 with real commits (`turns.head_sha`). That means real `git blame` is already correct for tracked files — including rename and line-shift handling — and blame's only remaining job is mapping the blamed commit SHA back to a turn through the `head_sha` reverse index. The hand-rolled snapshot annotator built in 03-01 is used only for content that lived exclusively as untracked files inside snapshots, which the real commit graph has no record of.

Output: `src/commands/blame.js`, `src/commands/blame.test.js`.
</objective>

<interfaces>
## Output format (exact — the tests assert on these strings)

Header, then a blank line, then one line per file line:

- Line 1: `Blame: <file>`
- If the untracked-snapshot fallback path was taken, line 2 is: `(untracked — annotated from turn snapshots)`
- Then one empty line
- Then per line: `` `${attr.padEnd(24)} ${String(line_no).padStart(4)}) ${content}` ``

Where `attr` is chosen as:

| Condition | `attr` value |
|-----------|--------------|
| Blamed commit maps to a turn | `` `${turn.session_id.slice(0, 8)}:${turn.turn_n}` `` |
| Blamed sha is all zeros (line not committed yet) | `(uncommitted)` |
| Blamed commit exists but is not a turn | `` `${sha.slice(0, 7)} (not a turn)` `` |
| Untracked-fallback line with no attributing turn | `(unattributed)` |

If `buildHeadShaIndex` reported collisions, print one warning to **stderr** before the header:
`` `git turn: warning: ${collisions.length} duplicate head_sha value(s) in turn history; attribution may be ambiguous` ``

## Error paths (console.error + process.exit(1), matching show.js lines 7-17)

| Condition | Message |
|-----------|---------|
| No session.json | `git turn: not initialized. Run \`git turn init\` first.` |
| Missing/empty `<file>` argument | `Usage: git turn blame <file> [--no-cache]` |
| File neither tracked in git nor present in any turn snapshot | `` `git turn: no history for ${file}` `` |

## Flags

`--no-cache` — forwarded to `listAllTurns({ noCache: true })`, same semantics as `log --no-cache`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv (`<file>`) -> git argv | User-supplied path reaches `git blame` and `git diff`; must be passed as data, never as a shell fragment or a parseable option |
| git object store -> stdout | Blamed file content and commit SHAs are echoed to the terminal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-11 | Tampering | `<file>` argument passed to `git blame` / `git diff` | mitigate | Always invoke through `gitSafe(argsArray)` with an explicit `--` separator before the path, so a path like `--upload-pack=evil` is treated as a filename and not an option. Path traversal needs no extra sanitization: git itself rejects paths outside the repository with a clean error, which `gitSafe` converts to null and the command reports as `no history for <file>`. Enforced by the acceptance criterion grepping for `'blame', '--porcelain', '--'` |
| T-03-12 | Spoofing | `head_sha`→turn attribution | mitigate | `head_sha` is not UNIQUE in the `turns` table, so a duplicate could make a line appear to belong to a different turn than it does. `buildHeadShaIndex` reports collisions and blame emits a stderr warning naming the count, so ambiguous attribution is visible rather than silent (03-RESEARCH.md Pitfall 4) |
| T-03-13 | Information Disclosure | blame output on stdout | accept | Blame prints file content the invoking user can already `cat`, plus commit SHAs they can already `git log`. Single local user, no privilege boundary crossed. The one discipline kept: the collision warning goes to stderr so stdout remains machine-parseable for the agent-facing use case documented in AGENTS.md |
| T-03-14 | Denial of Service | untracked fallback diff walk | accept | One `git diff` per turn per blame of an untracked file. This is a local performance characteristic on the user's own turn history, not a remotely-inflatable input — no third party can grow the turn count. Bounded in practice by `gc --keep-sessions` (default 10). Explicitly a performance concern, not a security one; revisit only if measured slow (03-RESEARCH.md Open Question 3) |
| T-03-SC | Tampering | package installs | mitigate | No packages installed in this plan; `package.json` gains no `dependencies` block. Legitimacy gate not applicable per 03-RESEARCH.md |
</threat_model>
