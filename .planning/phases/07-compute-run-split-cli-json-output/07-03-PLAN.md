<interfaces>
PHASE-WIDE compute/run CONTRACT (identical in Plans 07-02, 07-03, 07-04 — do not deviate):

- Signature: `compute(args, opts = {})` (for cost: `async function compute(args, opts = {})`). `opts.stderr` is an optional `(chunk: string) => void` sink; when absent, compute() performs NO writes. compute() never references `console`, `process.exit`, `process.stdout`, or `process.stderr`.
- compute() returns ONE string: each old `console.log(x)` becomes `lines.push(x)` with the IDENTICAL string `x` (embedded '\n' kept as-is), and `return lines.join('\n')`.
- Every old `console.error(msg); process.exit(1)` becomes `throw new Error(msg)` with the identical message; multiple consecutive console.error lines join with '\n' into one message.
- Every old direct `process.stderr.write(s)` becomes `if (opts.stderr) opts.stderr(s)` at the same point in control flow with the identical string.
- `--json` detected via `args.includes('--json')`; JSON built only with `JSON.stringify(<object>)`.
- run() (async variant): `async function run(args) { try { console.log(await compute(args, { stderr: (s) => process.stderr.write(s) })); } catch (e) { if (args.includes('--json')) { console.log(JSON.stringify({ error: e.message })); process.exit(1); return; } console.error(e.message); process.exit(1); } }`.
- Pre-phase test cases MUST NOT be edited; new tests appended only. Additions-only baseline commit: `98679b8`.

Progress-indicator decision (CONTEXT discretion item): the 'Fetching pricing data...\r' write and its 24-space clearing write stay INSIDE compute() at their current positions but go through `opts.stderr`. This is chosen over RESEARCH's "move into run()" suggestion because moving it would reorder stderr bytes relative to the not-initialized error (today that error prints before any progress text) and add a clearing write on the pricing-failure path — both would break D-05 byte-identity. Routing through the sink keeps compute() write-free when called without opts.

`--all` note: today `allSessions` is parsed but unused (listTurns always uses the current session). This plan does NOT change that behavior (out of scope); JSON shape is chosen so it stays valid if `--all` is wired later: every turn object carries its own `session_id`.
</interfaces>
